## 1.1.0

- Deploys network monitor `v3.2.0`. Earlier images attach to each pod's network interface by replacing the classic tc filter at priority 1, handle 1, the slot where some CNI plugins and network policy agents keep their own filter: `v3.0.x` on every kernel, `v3.1.0` on kernels older than 6.6. `v3.2.0` attaches with TCX on kernel 6.6 and newer, and elsewhere adds its own filter at priority 10. The chart refuses image tags older than `v3.2.0` (`kubeadapt.io/minimum-image-version`).
- Added: a ClusterRole for the reads pulse makes (`rbac.create`, on by default): `list` and `watch` pods, `get` nodes, `list` `ciliumenvoyconfigs.cilium.io`. Without it traffic is reported without pod and node identity.
- Added: export to the Kubeadapt agent (`config.export`). Pulse sends each node's traffic records to the agent's listener and presents a bearer token read from a mounted file, so a changed Secret takes effect without a restart. The `kubeadapt` chart turns export on and supplies the endpoint and the token; installed on its own, export stays off until `config.export.agentEndpoint` and a token Secret are set.
- Changed: the pod mounts the node's `/etc/cni/net.d` read-only at `/host/etc/cni/net.d` to tell the CNI and its encapsulation overhead, gets its memory limit as `KUBEADAPT_MEMORY_LIMIT_BYTES`, and resolves cluster Service names with `dnsPolicy: ClusterFirstWithHostNet`. It no longer uses the node's PID namespace and no longer mounts `/sys` or `/sys/kernel/debug`.
- Changed: the container stays privileged by default. `privileged: false` runs it with only `BPF`, `PERFMON`, `NET_ADMIN`, `SYS_RESOURCE` and `SYS_PTRACE` (see `values.yaml` for the platforms where that set is not enough).
- Added: `nodeRequirements` keeps the DaemonSet off nodes where its pod cannot start (non-Linux, AWS Fargate, virtual-kubelet). Optional and off by default: a priority class (`priorityClassName`, `priorityClass.create`), `istioAmbient`, `imagePullSecrets`, `podAnnotations` and `podLabels`.
- Removed: `config.collectionInterval` and `config.dumpBPFMaps`; `v3.2.0` does not read `EBPF_COLLECTION_INTERVAL` or `EBPF_DUMP_BPF_MAPS`.
- Upgrading with `helm upgrade --reuse-values` from an earlier release is refused, because it would keep the earlier image tag and settings. Use `--reset-then-reuse-values` (Helm 3.14 or newer) or `--reset-values -f <your values file>`.
