## 1.1.0

- **Least privilege.** The network monitor no longer runs privileged or in the node's PID namespace. The container keeps the Linux capabilities `BPF`, `PERFMON`, `NET_ADMIN`, `SYS_RESOURCE` and `SYS_PTRACE`, drops every other one, and runs without privilege escalation on a read-only root filesystem. `SYS_RESOURCE` is needed only on kernels older than 5.11, and `SYS_PTRACE` only for the container runtime inventory. Where an SELinux or AppArmor policy denies the BPF operations, set `seLinuxOptions`, or return to a privileged container with `privileged: true`. The release namespace must still allow the privileged Pod Security level, for `hostNetwork` and the added capabilities.
- **Minimum image.** The chart refuses an image tag older than its minimum release (the `kubeadapt.io/minimum-image-version` annotation). Older images attach to each pod's network interface with a classic tc filter at priority 1, handle 1, where some CNI plugins and network policy agents keep their own filter, and replace that filter: Kubernetes network policy then stops being enforced on the node. Releases before v3.1.0 do this on every kernel, v3.1.0 on kernels older than 6.6.
- **Nodes that ran an older image keep network policy off after the upgrade.** The new image does not put the CNI's filter back. On every node where an image older than the minimum ran:
  - **Cilium with classic tc attachment** (Cilium before 1.16, a kernel older than 6.6, or `enable-tcx: false`), Azure CNI powered by Cilium and GKE Dataplane V2: restart the Cilium agent pod on the node, for example `kubectl -n kube-system delete pod -l k8s-app=cilium --field-selector spec.nodeName=<node>`. On start it attaches its programs to every pod interface again.
  - **Amazon VPC CNI with network policy enabled:** drain the node and replace it, or delete the pods that run on it. The network policy agent attaches its filter to the interfaces of the new pods.
  - **Any CNI:** rebooting or replacing the node restores the CNI's filters.
  - Calico, Flannel, kindnet, kube-router, Weave, Antrea, OVN-Kubernetes, Azure CNI without Cilium, GKE without Dataplane V2 and Amazon VPC CNI without network policy keep no filter at that place and need nothing.
- **Export to the agent.** With `config.export.enabled`, which the kubeadapt chart sets, the network monitor sends each node's traffic records to the Kubeadapt agent once a minute, with a bearer token read from a Secret.
- **API access.** A ClusterRole (`rbac.create`) gives the read-only access the network monitor uses: list and watch pods, get nodes, and list `ciliumenvoyconfigs.cilium.io`. Without it, traffic is reported without pod and node identity.
- **Scheduling.** One pod on every Linux node, tainted nodes included, except AWS Fargate and virtual-kubelet nodes (`nodeRequirements`). Rollouts replace 25% of the pods at a time. There is no priority class by default, so the network monitor never evicts a workload; on a node without room its pod waits. `priorityClass.create` or `priorityClassName` give it a place on full nodes.
- **Upgrading.** Values written for an earlier release are refused at render, because `helm upgrade --reuse-values` would keep that release's image tag and privileges. Upgrade with `--reset-values -f <your values file>`, or with `--reset-then-reuse-values` (Helm 3.14 or newer).
- **Removed:** `config.collectionInterval` and `config.dumpBPFMaps`, which the network monitor does not read, and the `/sys` and `/sys/kernel/debug` host mounts.
